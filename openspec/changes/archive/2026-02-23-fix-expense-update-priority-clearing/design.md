## Context

The expense update endpoint uses a SQL query generated by sqlc. The query updates fields using `COALESCE` to preserve existing values when null is passed. However, `end_date` and `priority_group_id` fields are missing the `COALESCE` wrapper, causing unintended data loss.

Current query (buggy):
```sql
end_date = sqlc.narg('end_date'),
priority_group_id = sqlc.narg('priority_group_id'),
```

Expected query:
```sql
end_date = COALESCE(sqlc.narg('end_date'), end_date),
priority_group_id = COALESCE(sqlc.narg('priority_group_id'), priority_group_id),
```

## Goals / Non-Goals

**Goals:**
- Fix SQL query to use COALESCE for `end_date` and `priority_group_id`
- Ensure existing values are preserved when not explicitly provided in update request

**Non-Goals:**
- No changes to frontend code
- No API contract changes
- No changes to other expense fields

## Decisions

**Use COALESCE for all nullable update fields**: Consistent with other fields in the same query (description, amount, currency, category_id, expense_date, notes, recurring_type, start_date). This maintains the PATCH-like behavior where only explicitly provided fields are updated.

## Risks / Trade-offs

- **Risk**: None - this is a pure bug fix that restores expected behavior
- **Trade-off**: N/A - no alternatives considered; this is the correct fix
